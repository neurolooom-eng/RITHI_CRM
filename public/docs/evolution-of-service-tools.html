Evolution of Service Tools

Four systems have held the service record. The history of a machine is spread across all of them. This page says what each one was, the years it covered, how its calls were numbered, and how its data is kept in RITHI v2.0 — as Call History, apart from the live calls, so the whole history of a product can be read in one place.

  3. RITHI v1.0 — AppSheet, with the yearly sheets

    10-Jun-2022 → the move to RITHI v2.0

    Calls and visits were kept in one sheet per year. Every January the pending calls of the previous years were identified, listed and marked Old Calls; the year started fresh with the Old Calls carried in, and engineers closed both. For the record, the visit entries of the Old Calls were copied into the year sheet in which they happened.

    So one call can appear in two or more year sheets — registered in one year, closed in a later one. The 2025 DCCR register (the daily complaint review of that year) was also loaded, with its calls.

  4. RITHI v2.0

    The current system

    This application. Every live call, visit, spare and review is recorded here, and the workflows — DCCR, Field Failure, SLA, Objectives, hand stock — run on these records only. The calls of the earlier systems are kept beside them as history and take part in none of it.

How the earlier systems' data is kept here

Everything up to 2025 is history. It is loaded through Bulk Uploads → Calls → Call History, picking the Source (and, for a yearly sheet, its Year), and read on Machine History.

Apart from every workflow

Not in the call registers, Pending Calls, the Dashboard, SLA, My Workload, DCCR, Field Failure or the Objectives. Nothing is created from a historical call — no visit, review, FFR, notification or Product Database change.

As the file has it

Call status, solved date, item status and contract type exactly as written; every other column of the file kept with the call.

One call = UC No. + Call No.

The key is the pair, so a UC Number the old system used for two calls keeps both. Loading the same file again corrects it rather than adding it twice.

The same call twice: latest year shown, flagged

When a UC No. + Call No. arrives from another source or year — an Old Call in the next year's sheet, a call in two systems — the latest year's record is shown, the other is kept with it, and the call is flagged Duplicate. Nothing more is done about it until it is decided.
